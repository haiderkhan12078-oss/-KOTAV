Security / delivery controls

Evidence customers can review. Boundaries they can verify.

Trust starts before the first request is sent: authorisation, scope, data handling, traceability and review all need to be visible.

01 / AUTHORISE

Signed testing boundary

Hosts, access, dates, rate limits and Rules of Engagement are agreed before active testing begins.

02 / REVIEW

Specialist-reviewed delivery

Material findings are validated before they become customer conclusions.

03 / TRACE

Evidence history

Important actions and finding changes should remain attributable and tied to the engagement.

04 / HOST

EU evidence posture

Assessment infrastructure and stored evidence are positioned in Germany, with processing boundaries disclosed per engagement.

05 / OWN

Customer-owned outputs

Reports, evidence and portable artefacts should stay useful after the engagement rather than being trapped in a platform.

06 / LIMIT

Honest service limits

Recurring validation is not positioned as 24/7 incident response or as an automatic certification guarantee.

Operational restraint is a feature

Good security delivery says what it will not do.

Destructive payloads, persistence, real-data exfiltration and out-of-scope probing are not default behaviours. Explicit authorisation should control the test boundary.
